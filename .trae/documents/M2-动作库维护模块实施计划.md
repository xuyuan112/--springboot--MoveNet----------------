# M2 动作库维护模块实施计划

## Context

M1 已完成前后端联调，前端基础设施稳定（vue-tsc/vite build 通过）。M2 是管理端核心数据模块「动作库、规则与模板」，后续康复计划、训练记录、评估报告全部依赖动作版本与规则数据。

底层数据模型已在 model 层就绪（Action/ActionVersion/ActionRule/ActionTemplate 实体 + 枚举 + DTO + web-app 共享 Mapper），无需新建表。本次工作集中在 web-admin 的 Service/Controller/VO 四层和前端页面。

## 范围

覆盖接口文档 7.2 节全部 18 个端点（动作 CRUD + offline、版本管理 + publish + 校验、规则 CRUD、模板管理 + publish），以及前端 5 个页面 + 1 个 API 文件 + 路由/菜单接入。

## 后端实现

### 复用约束

- **Mapper 不复建**：ActionMapper / ActionVersionMapper / ActionRuleMapper / ActionTemplateMapper 已存在于 web-app 共享层，web-admin 通过模块依赖直接注入使用。
- **Service 范式**：主实体（Action/ActionVersion/ActionRule/ActionTemplate）使用 `IService<T>` + `ServiceImpl<XxxMapper, T>`；协作表（RehabPartDict/PlanItem 等）直接用 Mapper 注入。
- **Controller 路径**：按功能分包 `controller/action/`，`@RequestMapping("/admin/actions")` 等前缀，全部 `@OperationLog(module="ACTION", ...)`。
- **错误码**：使用 ResultCode 已有常量（VERSION_IMMUTABLE、STATE_CONFLICT、NOT_FOUND、VALIDATION_ERROR 等）。

### 新建 Service / ServiceImpl

#### AdminActionService（动作基础信息）

- `pageActions(page, size, targetPart, status, keyword)`：分页，keyword 匹配 name/description，关联 rehab_part_dict 显示 targetPartName。
- `createAction(ActionSaveRequest)`：校验 targetPartCode 命中字典；status 默认 DRAFT。
- `updateAction(actionId, ActionSaveRequest)`：仅 DRAFT 可编辑，否则 409 STATE_CONFLICT。
- `detail(actionId)`：返回动作 + 版本列表（按 versionNo 降序）。
- `offline(actionId)`：status → DISABLED；不删除数据，计划侧查询时过滤 DISABLED。

#### AdminActionVersionService（版本管理）

- `pageVersions(page, size, actionId, status)`：分页。
- `createVersion(actionId, ActionVersionSaveRequest)`：versionNo = 当前 action 最大 versionNo + 1；status 默认 DRAFT；algoConfig / motionSignature 原样存 JSON。
- `updateVersion(versionId, ActionVersionSaveRequest)`：仅 DRAFT 可编辑，否则 409 VERSION_IMMUTABLE。
- `publishVersion(versionId)`：
  1. 校验 version.status == DRAFT，否则 409 VERSION_IMMUTABLE。
  2. 校验该 version 下所有规则 scoreWeight 之和 = 1（容差 1e-6）。
  3. 校验 poseEngineId 非空。
  4. 校验 algoConfig JSON 可解析（可选，存 string 即可）。
  5. status → PUBLISHED；Action 的 status 若仍为 DRAFT 则同步改为 PUBLISHED。
- `detailVersion(versionId)`：返回版本 + 规则列表 + 模板列表。

#### AdminActionRuleService（规则 CRUD）

- `listRules(versionId)`：查询 ActionRule 列表，按 createdAt 排序。
- `createRule(versionId, ActionRuleRequest)`：校验 version.status == DRAFT，否则 409 VERSION_IMMUTABLE；symmetryPairRuleId 若提供须同 version 下存在。
- `updateRule(versionId, ruleId, ActionRuleRequest)`：同上草稿校验。
- `deleteRule(versionId, ruleId)`：同上草稿校验；物理删除（ActionRule 有 @TableLogic 逻辑删除）。

#### AdminActionTemplateService（模板管理）

- `pageTemplates(versionId, page, size)`：分页。
- `createTemplate(versionId, ActionTemplateSaveRequest)`：status 默认 ACTIVE。
- `publishTemplate(templateId)`：status → ACTIVE（已是 ACTIVE 则幂等）。
- `deleteTemplate(templateId)`：
  1. 校验未被 plan_item 引用（`plan_item` 表 `action_version_id` 关联，但模板本身通过 template_id 是否被引用需要检查 training_record 或 plan_item？根据接口文档 "删除仅限未被引用"，先查 plan_item 中无 template_id 引用即可）。
  2. 若被引用返回 409 FILE_IN_USE（语义同文件被引用）。
  3. 未被引用则逻辑删除。

## 实现顺序（推荐）

1. **后端 VO 层**（6 个 VO）
2. **后端 Service Interface + Impl**（4 个 Service，Impl 中先做动作/版本，再做规则/模板）
3. **后端 Controller**（4 个 Controller，可增量联调）
4. **前端 API 封装**（action.ts）
5. **前端路由 + 菜单**
6. **前端页面**：ActionListView + ActionFormDialog → VersionListView + VersionFormDialog → RuleEditor → TemplateListView
7. **打包 + 浏览器端到端联调**

## 验证方式

1. `mvn -pl web/web-admin -am clean package -DskipTests` 编译通过
2. `npx vue-tsc --build` 通过
3. `npx vite build` 通过
4. 浏览器联调：动作 CRUD → 版本创建 → 规则增删改 → 发布（权重和不等于1应拦截）→ 已发布后编辑应 409 → 模板创建/发布/删除

## 风险与注意点

- **algoConfig / motionSignature / featureSequence / keyframeIndex / keypointIndices**：后端均为 JSON String 原样存储，前端表单中作为 textarea（JSON 文本）输入，不做深层校验。
- **版本不可变**：publish 后 PUT version/rules 全部返回 409 VERSION_IMMUTABLE，前端按钮需按 status 动态禁用。
- **权重和校验**：规则列表中所有 scoreWeight 之和必须严格等于 1（BigDecimal 比较容差 1e-6），publish 时校验，前端列表页实时显示当前和。
- **部位字典复用**：targetPartCode 下拉直接使用已有的字典接口 `GET /admin/rehab-parts`（已联调通过）。
- **模板删除引用检查**：plan_item 表 action_version_id 关联版本而非 template_id，模板是否被引用需查 training_record 或新增引用表；若当前无引用链路，模板删除可暂不加引用检查（仅逻辑删除）。
