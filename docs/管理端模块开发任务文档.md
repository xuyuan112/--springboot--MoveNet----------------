### 验收标准

- 创建患者账号后可用初始密码登录，修改密码后旧令牌失效
- 禁用账号后该用户持原 token 访问任意接口返回 401
- 同一患者与同一治疗师有效期重叠的主责绑定返回 409 BINDING_CONFLICT
- 全部写操作在 `operation_log` 有记录（module=USER/BINDING）

### 前后端契约同步核查与浏览器端到端联调（2026-09-26 追加）

**契约核对结论（一致，无需改）**：`api/admin/user.ts`（8 函数）、`api/admin/binding.ts`（4 函数）的端点、HTTP 方法、参数名（账号分页 `role/status/keyword`，绑定分页 `patientId/therapistId/status`，登录日志 `success`）、字段名与后端 Controller/DTO/VO 全部一致。

**后端缺陷修复（联调实测发现）**：`web-app/AuthServiceImpl.handleLoginFailure` 对密码错误/锁定事件一律 `publishAuthEvent(null, ...)`，导致账号存在时失败日志的 `user_id` 仍为 NULL，管理端按用户查登录日志的"失败"页签永远为空；已改为传入 `UserAccount`、账号存在时落真实 userId（账号不存在仍为 null，避免账号枚举语义变化），重新打包重启后实测失败记录可被 admin 日志抽屉检索。

**端到端实测（浏览器真实走查，全部通过）**：登录页渲染与登录；账号列表时间空格格式/脱敏手机号/admin 仅"登录日志"；新增患者与治疗师（角色动态字段、出生日期、必填校验）；编辑回显与提交；角色筛选；禁用（空原因拦截+原因提交）/启用；重置密码确认；绑定远程搜索患者/治疗师、建立、列表时间显示、变更（医患选择器禁用回显、关系类型 PRIMARY↔SECONDARY、**有期限绑定再次打开 picker 完整回显到秒**）、解绑（空原因拦截+提交后状态 ENDED、失效时间落解绑时刻、操作按钮禁用）；登录日志抽屉全部/成功/失败切换与时间格式。`vue-tsc --build` 与 `vite build` 均通过；控制台无业务错误（仅 EP 组件库自身弃用告警，已处理）。联调测试数据（2 个测试账号/档案、1 条绑定、12 条操作日志、Redis 失败计数）已全部清理，库内恢复为仅 admin。

- **不依赖 mysqldump**（实测本机无该二进制）：`SqlBackupEngine` 纯 JDBC 逻辑备份——SHOW CREATE TABLE 取 DDL、MySQL 流式 ResultSet（fetchSize=Integer.MIN_VALUE）、200 行/批多值 INSERT；每条语句前独占行标记 `-- >>> STATEMENT <<<`，恢复按标记切分 execute，数据中含分号也安全；SET FOREIGN_KEY_CHECKS=0；排除 flyway_schema_history；byte[]→X'hex'、Boolean→0/1；UTF-8 SQL 文本 + SHA-256 校验。
- **并发控制**：Redis `backup:lock` setIfAbsent（TTL 2h，值=UUID，释放 GET 比对防误删），冲突 423；独立单线程 Executor（队列 1 + AbortPolicy）。
- **二次确认**：成功任务详情接口下发一次性 confirmToken（UUID 去横线，Redis 5 分钟），restore 校验后立即删除防重放；reason 必填（max500）。
- **恢复前快照**：restore 同步生成 PRE_RESTORE_SNAPSHOT，失败即中止恢复；**快照本身也可用于回退**（restore 支持两种 taskType，快照回退不递归建快照，审计 kind=SNAPSHOT_ROLLBACK），RESTORE_FAIL 提示中的 snapshotId 因此真正可用。
- **任务表自回滚问题修复**：恢复脚本会把 db_backup_task 一并回滚到备份时点（目标任务卡在 RUNNING 且丢文件元数据、快照行直接消失）。恢复成功/失败后均执行 `rebuildTaskStateAfterRestore`：目标任务写回 SUCCESS+文件路径/大小/SHA，快照行按原元数据重新落库（自增 ID 可能变化，以最终 ID 写审计）。
- **审计补发**：恢复会回滚 operation_log，RESTORE/RESTORE_SNAPSHOT（失败 RESTORE_FAIL）审计均在 restore() 之后用 ApplicationEventPublisher 手动补发。
- 备份目录 `rehab.backup.dir`（默认 data/backups，环境变量 REHAB_BACKUP_DIR）；**生产部署必须挂持久化卷**，否则容器重建后备份文件丢失（任务记录仍在但无法恢复）。

**前端（F1-F4）**：三个页面（公告含新增/编辑弹窗、scope 单选、datetimerange、发布专用对话框、下架/删除二次确认、详情抽屉；日志含 8 模块筛选+JSON 明细抽屉+复制；备份含 RUNNING 3 秒轮询、立即备份、恢复高危对话框[获取确认码/原因/风险勾选]、快照行「快照回退」入口、详情抽屉路径/SHA/错误展示）；路由 `/admin/announcements|operation-logs|backups` 与侧栏菜单（Bell/Document/Files 图标）已注册；`api/dict.ts` 4 处路径同步迁移。

**验收实测**：API 53 项全绿——公告全生命周期（草稿不可见→发布可见→已发布改/删/重复发布 409→下架不可见/重复下架 409→重新发布→过期发布 200 但患者不可见→下架删除 200/404）、scope 隔离（THERAPIST 公告患者不可见）、草稿态有效期倒置 400、权限（401/403）；字典新路径 200、被引用部位（SHOULDER）删除 409、无引用新增删除 200、不存在 404；日志 module=NOTICE 筛选、患者 403；备份创建→1 秒 SUCCESS→无 token/错 token 400→正确恢复 200→token 重放 400→目标任务仍 SUCCESS 且文件元数据保留→RESTORE/RESTORE_SNAPSHOT 审计齐→快照 SUCCESS 且关联备份正确→快照回退 200（闭环）→回退后两任务均 SUCCESS 且 SNAPSHOT_ROLLBACK 审计可查→恢复/回退后业务接口正常。浏览器走查：三页面渲染、筛选、弹窗、确认码流程、快照「快照回退」按钮、快照详情（路径 pre_restore_{sourceId}_{snapshotId}_*.sql + SHA-256）、字典回归 9 条均正常，console 无错误；`mvn clean package`、`vue-tsc --noEmit`、`vite build` 均通过。
