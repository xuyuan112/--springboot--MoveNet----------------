# 前端部署约定

> 本文件随 P0（前端工程拆分）创建，说明两个前端工程的独立部署方式。后端保持单服务，前端按角色拆站。

## 工程与端口

| 工程 | 路径 | 开发端口 | 打包产物 | 角色 |
|---|---|---|---|---|
| 管理端 | `frontend/` | `5173` | `frontend/dist/` | ADMIN |
| 用户端 | `frontend-app/` | `5174` | `frontend-app/dist/` | PATIENT / THERAPIST |

> 用户端同时承载患者端与治疗师端，按登录后的 `role` 由路由守卫分发到 `/patient` 或 `/therapist`。

## 开发环境（双端同时联调）

后端 Spring Boot 统一在 `localhost:8080`，`server.servlet.context-path=/api/v1`。

```powershell
# 终端 1：启动管理端
PS f:\...\frontend>          npm run dev     # http://localhost:5173

# 终端 2：启动用户端
PS f:\...\frontend-app>      npm run dev     # http://localhost:5174

# 终端 3：启动后端
PS f:\...\backend\web\web-app> mvn spring-boot:run
```

两个前端项目的 `vite.config.ts` 都配置了相同的开发代理：
- `/api` → `http://localhost:8080`
- `/minio` → `http://192.168.10.102:9000`（rewrite 去掉 `/minio` 前缀）

后端无需改动；两个前端各自向 `localhost:8080/api/v1` 发请求。

## 生产部署（Nginx 示例）

```nginx
# 管理端
server {
    listen 80;
    server_name admin.rehab.local;
    root /var/www/rehab-admin/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://localhost:8080;
    }
    location /minio/ {
        proxy_pass http://192.168.10.102:9000/;
    }
}

# 用户端
server {
    listen 80;
    server_name app.rehab.local;
    root /var/www/rehab-app/dist;
    index index.html;

    # P3 姿态引擎：ONNX Runtime Web 多线程 wasm 依赖 SharedArrayBuffer，
    # 必须开启跨源隔离（COOP same-origin + COEP require-corp）。
    # 缺失时端侧会自动降级为单线程推理（帧率下降但功能可用）。
    add_header Cross-Origin-Opener-Policy "same-origin" always;
    add_header Cross-Origin-Embedder-Policy "require-corp" always;

    location / {
        try_files $uri $uri/ /index.html;
    }
    # 姿态模型与 ort wasm 均为本地静态分发（禁止任何远端模型地址）。
    # 模型按 sha256 版本化、wasm 带 contenthash，可长缓存；wasm 需正确 MIME。
    location ^~ /models/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        types { application/octet-stream onnx; application/json json; }
    }
    location ^~ /ort/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        types { application/wasm wasm; application/javascript mjs; }
    }
    location /api/ {
        proxy_pass http://localhost:8080;
    }
    location /minio/ {
        proxy_pass http://192.168.10.102:9000/;
    }
}
```

> 开发环境无需额外配置：`frontend-app/vite.config.ts` 已注入同样的 COOP/COEP 响应头。接入第三方非跨源隔离资源（外部图片/iframe）时需给该资源补 `Cross-Origin-Resource-Policy: cross-origin`，否则会被 COEP 拦截。

## 构建脚本

```powershell
# 管理端
PS f:\...\frontend> npm run build       # 输出到 frontend/dist

# 用户端
PS f:\...\frontend-app> npm run build   # 输出到 frontend-app/dist
```

## 关键注意点

1. **Token 键名一致**：两端共享 `localStorage` 键 `rehab_token` 与 `rehab_user`，同域名下单点登录行为保持一致。
2. **端口不冲突**：开发环境用户端用 `5174`（管理端已占 `5173`）。
3. **姿势引擎仅在用户端**：`onnxruntime-web` 及 `.onnx` 模型仅在 `frontend-app` 安装，管理端不引入。
4. **前端产物清理**：管理端瘦身后第一次构建务必 `rm -rf dist`（或 `vite build --emptyOutDir`），否则旧 `PatientHomeView`/`TherapistHomeView` chunk 残留。
5. **姿态资产本地准备（P3）**：模型与 wasm 不随仓库分发时，在 `frontend-app/` 执行 `npm run prepare:pose-assets` 生成 `public/models/`（onnx + manifest.json，含 sha256 与 engineId）与 `public/ort/`；构建后模型/wasm 需随 `dist/` 一同发布，运行时只允许加载同源 `/models`、`/ort`，不得配置任何远端模型地址。页面需 **HTTPS 或 localhost** 与摄像头授权才能训练。
### Docker 用户端（MoveNet）

Docker Compose 提供独立的用户端 Nginx：它挂载 `frontend-app/dist`，端口为 `5174`，并显式发布 `/models/` 与 `/ort/`。发布前先在 `frontend-app` 执行 `npm run build`，然后在 `deploy` 目录执行 `docker compose up -d nginx-app`，使用 `http://localhost:5174` 访问摄像头训练页面。

管理端仍使用 `frontend/dist` 的 80 端口。不要把两个工程的 `dist` 目录互相挂载；否则用户端模型和 WASM 资源会返回 404。
