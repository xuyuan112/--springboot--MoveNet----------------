## P3 患者端 · 姿态引擎集成（ONNX Runtime Web 本地推理，需求 3.1.3 + 6.3 全链路）✅ 已完成（2026-10-01，患者端 vue-tsc + vite build / 管理端 vue-tsc / 后端 mvn clean package 均通过；V4 迁移已于后端重启时执行并核对 3 条 action_version 回填成功；剩余摄像头真人走查需真机/授权环境，P4 提交接口在下包衔接）

>
> 落地补充（相对原表）：① 真实 `pose_engine_id = movenet-lightning-web@1ad4f8d6c2f7-ortweb1.30.0`（模型 9,413,268 字节，sha256 前 12 位 `1ad4f8d6c2f7`，来源 hf-mirror 本地分发），V4 Flyway 迁移回填历史占位值（2026-10-01 17:47 重启后已执行，3 条 action_version 全部回填核对一致）；引擎一致性为端侧+服务端双层闸门（start 上送 X-Pose-Engine-Id，已实测正确头 200 / 错误头 422 / 无头兼容 200）；② 编排器 `index.ts` 实时因果管线 + 结束时对原始帧缓存做**非因果确定性复算**（评分唯一口径，保证可复现），实时计数仅作展示；③ P3-F9 结束后汇总仅在端侧呈现（六维分/纠错聚合/质量等级），**P4 训练记录提交接口与断网 client_request_id 重试未在本包实现**，不假造接口；④ 状态机/签名校验对脏签名做**方向一致性矫正**（起止区间完备时方向以"峰值中位 vs 起始中位"的升降为准，治疗师误标 EXTEND 不会导致永远无法触发），周期起点角取 READY 休息窗内最放松位（ROM 不再被滞后腰斩），节奏分=60% 期望时长高斯吻合 + 40% 周期间节拍一致性，纠错规则在 READY 休息相位不提示（ACTION_MISMATCH 脉冲除外）；⑤ 纯算法合成冒烟（3 周期屈肘，FLEX / 真 EXTEND / 误标 EXTEND 三场景）计数 3/3、签名全匹配、ROM≈90°，同一批原始帧跑两遍评分逐位一致（可复现性满足需求 7.7）。

## 执行顺序与依赖

```
P0（前端拆分）──► 一切前端任务的共同前置
P1（资料） ──► P2（计划/任务+调度）──► P3（姿态引擎 ONNX Runtime Web）──► P4（训练提交/记录）──► P5（趋势/报告/收藏/AI）
                                        │         ▲
P6（治疗师计划）──依赖 P2 调度联调 ───────┴─────────┘ P6 可与 P3/P4 并行起步（种子数据 + P3 参数快照）
P7（训练数据/报告审核）──依赖 P4 数据、P5 报告生成
P8（咨询）──依赖 P1 绑定校验，独立性强，可插队在 P5 后
```

- **P3 是关键路径**：患者训练闭环（需求 4.1）依赖其可用；建议 P3-F1（ONNX Runtime Web 推理层）最先做技术验证（模型加载/帧率/降级），验证通过后并行推进其余管线模块。
- 每个任务包交付节奏沿用管理端：后端编译+API 实测（curl + Redis TCP 验证码链路）→ 前端 vue-tsc/vite build → 浏览器端到端走查 → 更新本文档为完成态。
- 联调种子数据：P2~P5 阶段用 SQL 直插 PUBLISHED 计划/任务，P6 完成后替换为真实链路。

## 代码质检清单（每包收口执行）

1. `mvn clean package` 通过（迁移后必须 clean，防 target 残留）
2. 新 Mapper 放 model 对应域子包；VO 放 web-app；Controller 按端/功能独立文件
