选题的意义、目的、主要内容和主要研究方法：
1、课题来源
近年来，随着我国人口老龄化进程加快以及慢性疾病、术后康复和运动损伤人群的持续增加，康复医疗需求快速增长。康复训练的效果高度依赖"按计划、按标准、长期坚持"，但传统居家康复主要依靠患者自行模仿动作，普遍存在指导不足、动作不规范、训练过程缺乏客观记录等问题；治疗师难以持续观察患者的训练过程，也难以依据客观数据及时调整康复方案。随着深度学习与人体姿态估计技术的发展，普通摄像头采集的视频已经能够在端侧实时识别人体关键点，这为低成本、非接触式的康复动作评估提供了新的技术路径。
MoveNet 是 Google 提出的一种轻量级人体姿态估计模型，能够借助 TensorFlow.js 在浏览器端以较高帧率完成单人 17 个人体关键点的实时推理，具有部署简单、无需专用硬件、原始视频不出本地等优点；Spring Boot 则是当前主流的 Java 后端开发框架，具有开箱即用、生态完善、便于构建 RESTful 服务的特点。基于此，本课题拟构建一个基于 Spring Boot 框架、融合 MoveNet 姿态评估模型的康复训练辅助平台，将"计划—训练—评估—报告"的康复流程数字化，使患者在居家场景下也能获得实时的动作反馈，同时帮助治疗师基于客观数据管理患者的康复进程。该课题来源于康复医学与计算机视觉交叉领域的实际需求，具有较强的现实意义和工程实践价值。
2、研究目的和意义
本课题旨在解决传统居家康复训练中"指导不足、动作不规范、训练数据缺失"的核心问题，具体目标包括：
（1）构建面向康复患者、康复治疗师和系统管理员的多角色协同平台，实现"患者与治疗师绑定→治疗师制定专属康复计划→患者按计划完成训练→系统进行姿态评估与纠错→保存训练记录→治疗师审核评估报告→调整计划"的闭环管理；
（2）在浏览器端实现基于 MoveNet 的实时人体姿态评估，通过关键点质量门控、时序平滑与遮挡修复、骨架归一化等处理，计算关节角度、关节活动度（ROM）、角速度、对称性和稳定性等运动特征，并对康复动作进行多维加权评分、计数与实时纠错；
（3）在保证隐私的前提下保存训练汇总数据，支持训练趋势可视化与阶段性评估报告生成，为治疗师调整康复方案提供客观依据。
研究意义主要体现在两个方面：在应用层面，平台降低了居家康复对专业设备与人工陪护的依赖，使患者能够获得可量化、可追溯的训练反馈，有助于提高训练的依从性与规范性；在技术层面，本课题探索了轻量级姿态估计模型在端侧康复评估场景下的工程化落地路线，通过可解释的后处理与评分链路，为同类低成本、隐私友好的康复辅助系统提供参考。
3、国内外研究现状及发展趋势
在国外，人体姿态估计研究起步较早，OpenPose、HRNet 等模型在精度上不断提升，MediaPipe、MoveNet 等轻量级方案则将推理能力下沉到移动端和浏览器端；在康复领域，国外已经出现将姿态估计用于步态分析、关节活动度测量和理疗动作质量评估的研究与产品，并尝试通过 Transformer 等方法实现二维到三维的姿态提升，以提高评估的完整性与准确度。相关研究还提出了部位亲和场（PAF）末端纠正、非线性最小二乘（LM）轨迹精修、多尺度图卷积动作识别、时间注意力等方法，用以提高关键点精度和动作识别能力。
在国内，基于人体姿态估计的康复训练评估研究近年来发展较快。郑州大学的《基于人体姿态估计的康复训练动作检测方法研究》（2024）系统研究了面向康复训练的动作检测流程；电子科技大学的《面向视频的太极拳康复训练评估研究与实现》（2025）探索了面向视频的康复训练评估方法。整体来看，国内相关系统多聚焦于动作识别或单一指标测量，面向普通家庭、将姿态评估与康复计划管理打通的综合性平台仍相对缺乏；同时，高精度方法往往依赖服务器端 GPU 算力或大规模模型训练，部署成本高，并存在患者视频上传带来的隐私风险。
发展趋势主要体现在四个方面：一是模型轻量化与端侧化，在保证精度的前提下降低算力门槛；二是评估可解释化，从"仅给出分数"转向"给出可追溯的证据与纠错建议"；三是隐私最小化，原始视频在本地处理、仅上传汇总指标；四是康复流程闭环化，将评估结果与康复计划、评估报告联动，真正服务于治疗决策。
4、主要研究内容
本课题以"三端 + 六大业务域"为主线开展研究与实现，具体内容包括：
（1）账户与权限模块。实现康复患者、康复治疗师、系统管理员三类角色的注册登录、密码加密存储与个人资料维护，支持管理员建立、变更和解除患者与治疗师的绑定关系；所有接口执行 JWT 认证、角色校验和对象级归属校验。
（2）康复计划与任务模块。支持治疗师为负责患者制定专属康复计划，设置动作、组数、次数、幅度、时长、频率等参数，并支持计划版本化；系统按计划频率自动生成每日训练任务，支持任务进度与三级完成度统计。
（3）实时姿态评估模块（核心）。浏览器在患者授权摄像头后加载 MoveNet 模型，逐帧识别 17 个人体关键点，依次完成入场质量检查、置信度门控、时序平滑与遮挡修复、骨架归一化、运动特征计算、动作阶段状态机与计数、多维加权评分和实时纠错，训练结束后仅上传汇总指标与质量信息。
（4）训练记录与报告模块。支持按日期、计划和动作查询训练记录，以图表方式展示训练趋势、得分趋势、达标率与纠错类型；系统预生成阶段性评估报告草稿，由治疗师补充结论并审核生效。
（5）公共内容模块。提供标准动作演示、健康科普等公共康复知识，支持按康复部位、分类和关键词筛选与收藏。
（6）咨询与通知模块。支持患者向负责治疗师发起文字或图片咨询并由治疗师回复；在无治疗师绑定时提供带免责声明的 AI 康复知识问答，并提供平台公告等通知能力。
系统开发平台：（1）操作系统：Windows 10/11；（2）数据库：MySQL 8.0；（3）缓存与中间件：Redis 7；（4）对象存储：MinIO；（5）开发环境：IntelliJ IDEA、Visual Studio Code；（6）开发语言：Java 17、TypeScript；（7）构建与部署：Maven、Vite、Docker Compose、Nginx。
5、拟采取的技术路线与试验方案
本系统采用 B/S 架构与前后端分离的开发方式，后端基于 Spring Boot 提供版本化的 RESTful API（统一以 /api/v1 为前缀），前后端通过 JSON 交互；姿态评估相关的计算全部在浏览器本地完成，从架构层面保证"原始视频不出本地"的隐私边界。
5.1 前端技术
前端采用 Vue 3 与 TypeScript 开发，使用 Vite 构建，配合 Vue Router 实现三端按角色的路由与懒加载，使用 Pinia 进行状态管理，使用 Element Plus 作为 UI 组件库，使用 ECharts 完成训练趋势等数据可视化；姿态引擎采用 TensorFlow.js 封装的 MoveNet 模型，可在 WebGL 与 WASM 后端之间切换。
5.2 后端技术
后端采用 Java 17 与 Spring Boot 3 构建，使用 Spring Security 与 JWT 实现认证授权，使用 MyBatis-Plus 作为持久层框架并配合 Flyway 管理数据库迁移；使用 MySQL 8.0 存储业务数据，使用 Redis 实现缓存、限流、幂等和分布式锁，使用 MinIO 存储动作演示视频、附件等非结构化资源并通过短时预签名 URL 访问；使用 springdoc-openapi 生成接口文档。
5.3 姿态评估算法链路
评估算法在 MoveNet 推理之后增加一条确定性的端侧"后处理与评估链"：摄像头授权后先进行单人入场质量检查与目标跟踪锁定，再进行三级置信度门控、中值/EMA 平滑、短缺口插值和骨长方向约束的遮挡修复，随后进行平移/尺度/轴向归一化，计算关节角度、ROM、角速度、角加速度、对称性与稳定性，经动作签名（motion_signature）合规校验和阶段状态机计数，最终输出幅度、保持、节奏、稳定、对称与模板相似度六维加权评分，并按严重度生成纠错提示。关键安全规则为：有效帧比例过低或修复比例过高时标记为质量不足，只记录不计分；动作签名不匹配时拒绝计数并提示重新开始。
5.4 试验方案
在离线与在线两个层面开展验证。离线层面对标准示范动作和测试样本进行人工标注，验证主要关节角度误差、计数准确率、目标动作通过率与非目标拒绝率等指标，并验证同版本同数据评分的一致性；在线层面关注单帧后处理耗时、端到端延迟、质量指标分布与纠错准确性，并通过单元测试、集成测试和端到端测试保证系统质量。
6、研究基础
6.1 在该领域已取得的研究成果
已经掌握 Java、Spring Boot 的开发方法，熟悉 MySQL 数据库设计与 MyBatis-Plus 的使用，具备 Vue 前端开发和前后端分离项目的实践经验；已经完成本平台的调研、功能需求分析、数据库设计与接口设计，搭建了后端多模块 Maven 工程和前端三端页面骨架，实现了登录认证、角色与对象级权限校验等基础能力，并完成了姿态评估链路的算法方案设计与部分前端实现。
6.2 试验条件
a. 已经具备的条件：具备 Java、Spring Boot、Vue 与 TypeScript 的开发基础，熟悉 IntelliJ IDEA、Visual Studio Code 等开发工具；具备普通摄像头与个人计算机，能够满足浏览器端 MoveNet 推理与测试的需要；已具备 MySQL、Redis、MinIO 等环境的本地部署条件。
b. 未具备的条件及提出的解决方案：对康复医学专业知识、动作评估阈值设定以及大规模姿态数据的标注经验不足。解决方案：查阅康复医学与人体姿态估计相关文献，参考已公开的康复动作评估研究与标准；在专业教师和资料指导下确定关节角度阈值与评分权重，并通过小样本人工标注进行校验；采用先小范围试用、再逐步迭代的方式完善评估参数。
7、预期达到的目标
（1）完成一个可在浏览器访问的康复训练辅助平台，实现患者、治疗师、管理员三类角色的主要功能；（2）实现基于 MoveNet 的实时姿态评估，能够在普通计算机上实时完成关键点识别、动作评分、计数与实时纠错，主要关节角度误差与动作计数准确率达到预期指标；（3）形成"计划—训练—评估—报告"的完整闭环，训练数据可查询、可追溯、可统计；（4）原始视频在本地处理、仅上传汇总数据，满足隐私最小化要求；（5）完成符合规范的毕业设计论文与相关开发文档。

2.1 引言
在人口老龄化与慢性病管理需求不断增长的背景下，康复训练已成为改善患者运动功能、提高生活质量的重要手段。然而，传统居家康复普遍面临"患者依从性差、动作规范性难以保证、训练数据缺失、治疗师难以持续跟踪"等现实问题，训练效果很大程度依赖患者的主观理解和自律。随着计算机视觉与深度学习技术的发展，人体姿态估计技术已经能够从普通摄像头视频中实时、非接触地提取人体关键点，为康复动作的量化评估提供了新的手段，也为解决上述问题带来了可能。
与此同时，Spring Boot 与 Vue 等前后端技术的成熟，使得构建一套结构清晰、易于部署和扩展的康复管理平台成为可能。本课题旨在设计并实现一个基于 Spring Boot 框架、融合 MoveNet 姿态评估模型的康复训练辅助平台：在患者端，通过浏览器调用摄像头，在本地完成姿态识别、动作评分、计数与纠错；在后端，保存训练汇总数据、管理康复计划与评估报告，并由治疗师审核后形成阶段性结论。该平台以隐私最小化和评估可解释为设计原则，力求在普通设备条件下为居家康复提供可量化、可追溯的辅助支持，为康复训练的数字化与智能化提供有益探索。
2.2 系统业务模块以及功能模块
康复训练辅助平台以优化康复训练质量与效率、保障患者隐私为核心目标，围绕康复患者、康复治疗师、系统管理员三类角色设计功能，以下是各角色的主要功能说明：
（1）康复患者：可以注册登录并维护个人资料（身高、体重、康复部位、禁忌说明等），查看负责治疗师和当前康复计划，查看并按当日任务进行训练；在训练过程中授权摄像头进行实时姿态评估，获得动作评分、计数与纠错提示；训练结束后提交结果，查看训练记录、训练趋势和已生效的评估报告；浏览并收藏公共康复知识；向治疗师发起人工咨询，或在无治疗师绑定时使用带免责声明的 AI 康复问答。
（2）康复治疗师：可以登录治疗师端，在工作台查看负责患者列表、计划状态、近期完成度和待办事项；按姓名、康复部位和计划状态筛选患者，查看患者档案与历史计划；为患者制定和调整专属康复计划，设置动作、组数、次数、幅度、时长和频率等参数；查看训练数据与得分趋势，审核由系统预生成的评估报告并使其生效；导出训练汇总数据；回复患者咨询并查看公告。
（3）系统管理员：可以创建、启用或禁用患者和治疗师账号并重置密码；建立、变更和解除患者与治疗师的负责关系；维护动作库、评估规则和标准动作模板，并在修改时创建新版本；审核公共内容，发布和编辑平台公告；维护康复部位等字典；查看操作日志与安全日志，执行数据备份与恢复。
2.3 总结
本系统采用 B/S 模式，基于 Spring Boot、Vue 3 和 MySQL 技术进行开发，姿态评估由 MoveNet 在浏览器端完成；系统设计遵循软件工程的一般步骤，包括系统调研、需求分析、系统设计、系统实现与系统测试等环节。在功能上实现了账户与权限、康复计划、实时姿态评估、训练记录与报告、公共内容、咨询与通知等模块；在安全与隐私上采用 JWT 认证、对象级权限校验和"原始视频不出本地"的设计。整体上，系统结构清晰、模块划分合理、界面简洁易用，能够较好地满足居家康复训练辅助的实际需要。
