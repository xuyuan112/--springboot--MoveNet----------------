## 补充：PowerDesigner 中 Entity 与 Association 的转换

用户追问：普通实体能否直接转成 Association。

结论（已查证 SAP 官方文档 + 社区教程）：

- PowerDesigner **没有**「Entity → Association」的一键转换命令。
- 官方支持的方向是反过来的：选中 M:N 的 Relationship → 右键 **Change to Entity**，把联系转成独立实体。
- `Association` 主要适用于**三个及以上实体之间的关联**（官方例子：录音带/顾客/商店之间的「租借」），或没有独立标识符的纯关联；生成 PDM 时会把两端实体的 identifier 全部带入关联表。
- 本项目 `patient_therapist` 有独立主键 `binding_id`，且被 `rehab_plan.binding_id`、`consultation.binding_id` 引用，属于「两个实体之间、带属性、有自身标识符」的桥接表 → **用普通实体矩形画是正确的**，不需要改成 Association。
- 重要坑：不要在 relationship（联系线）上直接加属性（双击连线 → Attributes），CDM→PDM 转换时这些属性会被忽略，生成的中间表只剩两个外键。必须把联系转成实体，或用 Association 承载属性。

## 重要修正：patient_therapist / patient_rehab_part 的关系线应连向 user_account

用户追问「患者档案里是不是缺少患者用户ID、治疗师用户ID」。复核《数据库设计.md》后确认：

- `patient_therapist.patient_id` / `therapist_id` 引用的是 **`user_account.user_id`**（11.3 节明确写「患者/治疗师用户ID」），不是 `patient_profile_id` / `therapist_profile_id`。
- `patient_rehab_part.patient_id` 同样引用 `user_account.user_id`（11.4.1 节明确标注）。
- `patient_profile.user_id`、`therapist_profile.user_id` 引用 `user_account.user_id`（1:0..1）。
- 因此 9 节关系总览写的是 `user_account M─N patient_therapist`，而非 `patient_profile M─N therapist_profile`。

**结论修正**：之前建议「患者档案 1—N 患者治疗关系 N—1 治疗师档案」是**不准确**的——那样生成 PDM 会得到 `patient_profile_id` / `therapist_profile_id`，与现有 SQL 不一致。正确画法是**两条关系线都从 `user_account` 连向 `patient_therapist`**，用不同 Role 名（作为患者 / 作为治疗师）区分；`患者康复部位` 同理，从 `user_account` 连出。原图中「作为患者」「作为治疗师」两条线方向是对的，只有「创建」那条应删除。

补充原则：CDM 中外键**不手写为属性**，由 Relationship 在 Generate PDM 时自动迁移；同一对实体间有多条关系时**必须设置不同 Role 名**，否则生成的外键列名会冲突。

用户要求同样检查模块二，包含 7 个实体：康复部位字典、标准动作、动作版本、动作评估规则、标准动作模板、动作模板采样记录、MinIO 文件对象。

- **重灾区**：动作评估规则（字段最多，且含大量 JSON/Decimal 类型）、MinIO 文件对象（含删除时间、创建人ID）。
- **需删除的关系线**：所有表里的 `创建人ID` 指向 user_account 的审计关系不应在模块二 CDM 中画出。
- 已更新《CDM属性分层检查报告.md》第六节，并绘制模块二规范 CDM 概念模型图。
- 首版模块二 CDM 图布局拥挤，用户要求重画。**重画后的布局方案（可复用）**：左列主干纵向排「康复部位字典 → 标准动作 → 动作版本 → 动作评估规则」，右列排「标准动作模板 → 动作模板采样记录 → MinIO 文件对象」，动作版本用一条水平箭头连到右列首个实体；自关联画成实体右侧的圆角回环 + 两行文字标注；属性在框内按「2 个一行」合并以压缩高度；配色用 c-blue(50/600) 普通实体 + c-teal(50/600) 标注关联实体；卡片宽约 190–280px，超过 260px 易挤，超过 4 个属性要分行。
- **易混点澄清（用户曾误记）**：模块二里唯一的「关联实体」是 `动作模板采样记录`（两端指向 `标准动作模板` 和 `MinIO 文件对象`，见数据库设计 11.9 的两个外键 template_id / file_id）。`动作评估规则` 不是关联实体，只是 `动作版本` 的**从属实体**——它的外键只有 `action_version_id`（外加自关联 `symmetry_pair_rule_id`，数据库设计 11.7），只有 1 个父实体。**判定标准：父实体数量 ≥2 且指向不同实体 → 关联实体；只有 1 个 → 从属实体。** 另外这两个都不是 M:N（一个是父子 1:N，一个是 1:N + N:1 串联），所以模块二 CDM 整块不出现 PowerDesigner 的 Association 胶囊。
